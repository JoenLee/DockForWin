# 2026-11-14 性能与后端审查：修改与测量

测量机器同上一轮（Intel UHD 核显驱动 2560×1600 / 165 Hz / 150%，RTX 4060 不接屏），用户自己的配置副本。帧数是 WGC 观察窗口的合成更新（MinUpdateInterval 1 ms），不是 Rendering 回调次数，也不是 PresentMon 物理帧；对比都关了分层编译，单次波动约 ±10%。

## 改了什么

### 设置窗口滚动
- 整窗 `OpacityMask` 改为圆角 `Clip`（`SettingsShellWindow.Floating.cs`）。遮罩让整窗每帧进一次中间层；只要窗口里有任何动画在跑，哪怕画面没变也会整窗重绘（滚动停下后约 1.5 s 内以约 16 fps 重绘，闲置 CPU 最高 25–46%）。圆角抗锯齿检查照常通过。
- 平滑滚动期间页面内容挂 `BitmapCache`，滚动结束或被打断时取消（`SettingsScrollMotion.cs`）。滚动时页面只是一张移动的贴图，控件阴影和顶栏对页面的采样不再每帧重画。滚动中暂停悬停（指针下滑过的行不会让缓存失效），点击会先停下滚动。
- 阴影的缓存挂在父级：`BitmapCache` 不包含元素自己的 Effect，挂在带 `DropShadowEffect` 的元素本身几乎没用（实测 +3–8 fps）。按钮、下拉框、开关、滑块按钮、红绿灯的阴影，以及侧栏和导航胶囊的阴影，都包了一层带缓存的父容器，阴影参数不变。
- 顶栏模糊放进 `BitmapCache(0.5)`：模糊半径按 DIP 计，视觉半径不变，像素量为原来的 1/4。
- 窗口仍是分层窗口。试过控制中心那种 DWM 合成的非分层窗口（滚动还能再快 30–40%），但设置窗口带标题栏/可调边框样式，Win11 会把扩展进客户区的边框画成实色，圆角处变成方的白色；要透明就得去掉可调边框，会破坏原生缩放和贴靠，因此没有采用。后来做过一版去掉可调边框、自己处理拖边缩放的实现（程序坞页滚动 34–44 → 67–77 fps，外观不变，代价是失去贴靠），暂未合入。

### 设置页的滚动条与信息密度
- 默认窗口装得下的页面不再出现滚动条。原来每页最后一组的下边距（26）和页面底边距（28）叠在一起，单这段留白就把通用页等顶出了滚动；现在统一成 20（`SettingsPageHost.TrimTrailingSpace`，高级设置的详情页同样处理）。
- 小组件首页卡片高 164 → 124，"N 种模板 · 查看与设置"贴卡片底边，六张卡片一屏放下。
- 页面顶部 18 → 10，实时预览开关下 18 → 10，分组间距 26 → 22，带说明的链接行上下各少 2；默认窗口 880×620 → 880×640（仍受工作区限制）。
- 默认大小、中文界面逐页测量：通用、小组件、控制中心、图标与倒影及其他详情页不再滚动；程序坞首页（约 +330）和控制中心"模块与排列"（约 +900）内容本身超过一屏，保留滚动。英文界面"图标与倒影"仍超出 29。窗口缩小到装不下时照常出现滚动条。

### 设置里拖滑块
- 圆角滑块每次数值变化只更新两块预览玻璃板的参数；图标、背景截图和桌面预览仍走 60 ms 节流的 `FlushPreview`（`SettingsWindow.Appearance.cs`）。
- 预览阴影原地更新，不再每次新建 `DropShadowEffect`；预览背景截图（`RenderTargetBitmap`）只在裁切区域或尺寸变化时重渲（`SettingsWindow.Appearance.cs`、`SettingsWindow.cs`）。

### 控制中心关闭后整窗泄漏
- `LiquidGlassEffect` 原来所有实例共用三个静态 `PixelShader`。WPF 会让每个 `ShaderEffect` 订阅其着色器的内部 bytecode-changed 事件（冻结也照样订阅），静态着色器因此持有每个创建过的效果 → 元素 → 整个窗口：每关闭一次控制中心就留下一整个窗口（真实程序约 10–25 MB）。现在每个效果持有自己的 `PixelShader`。设置窗口重开（取消/保存）里的玻璃预览同样受益。

### 程序坞背景采集
- 改走控制中心已验证的 `GlassBackdropService.ReadPixels`（从上到下、不读被不透明窗口挡住的部分、不经过 GDI+、未变直接返回），并复用一张 `WriteableBitmap` 原地写入。原来背景每变一次就新建约 1 MB 的位图，落在大对象堆，背后有视频或滚动页面时每几帧就一次 Gen2 回收。

### 后台逻辑
- 前台切换应用时的"最近应用"不再立即整份写 settings.json，3 s 内合并为一次保存（退出时 Program 仍会保存）；最近应用的 `File.Exists` 结果缓存 30 s（`DockViewModel.cs`）。
- `AddAsync` 在 await 之后再查一次是否已固定，拖放和文件选择并发时不会重复固定。
- `SettingsService.Save` 写临时文件后 `Flush(true)` 再替换，失败时删除临时文件。
- 刷新率试用只做本次会话的临时切换（不带 `CDS_UPDATEREGISTRY`），点"保留"时才写入；进程崩溃或被结束时不会把试用值留在系统里（`DisplayControlService.cs`）。
- `WindowTracker.Refresh` 捕获并记录异常（原来 async void 异常会进全局异常处理）；窗口事件改为真正的防抖（停 180 ms 后刷新，持续事件下最长 1 s 一次）。
- 任务栏 UIA 扫描从每 1.5 s 改为每 5 s，指针在任务栏上时（低级钩子本来就收到移动）最多每秒补扫一次（`ControlCenterEntryService.cs`）。单次扫描实测约 73 ms，explorer 端约 31 ms CPU。
- 控制中心轮询里的 `ReadFocus()`（WinRT 同步调用）移出 UI 线程；亮度读取复用已连接的 WMI scope。
- 小组件拖放在读取桌面图标（最长数秒）之后才取设置快照，不再覆盖期间的其他保存；`e.Handled` 在 await 之前设置。
- AppsFolder 查找结果缓存（未找到的缓存 10 分钟）；保持唤醒部分失败时先清除电源请求；Wi-Fi 位置权限提示每个进程只记一次日志。

## 结果

| 场景 | 改动前 | 改动后 |
|---|---|---|
| 设置窗口滚轮滚动（程序坞/控制中心/通用页），负载较轻时 | 27–35 fps，p95 60–73 ms | 46–74 fps，p95 18–42 ms |
| 同上，机器负载较高时（同一时段前后紧挨着测） | 18–22 fps，p50 42–55 ms | 26–48 fps，p50 18 ms |
| 设置窗口滚动停止后闲置 | 约 16 fps 整窗重绘，最高 46% CPU | 0 帧 |
| 控制中心开关 12 次后仍存活的窗口（进程内，每次强制 GC） | 12/12，私有内存每次 +11 MB | 0/12，每次约 +1–3 MB |
| 程序坞背后页面滚动 4 s（受控时段） | CPU 46–47%，分配 75 MB，Gen2 回收 22–24 次 | CPU 20–24%，Gen2 回收 1 次 |
| 控制中心动画（展开/快速来回/滑块/关闭） | 85 / 109 / 120 / 103 fps | 95 / 109 / 125 / 106 fps（无退化） |
| 控制中心打开后闲置 CPU（测量框架） | 23% | 15.5% |

真实程序隔离运行、16 次开关控制中心：改动前私有内存 200 → 747 MB；改动后最高 645 MB，GC 后回落到 409 MB（改动前同一步骤为 481 MB）。真实程序的数值受当时屏幕内容和 GC 时机影响很大，以进程内强制 GC 的结果为准。设置窗口打开后闲置 CPU 11–19% → 5–7%。
后半段测量时用户机器负载变化大，同一配置两次之间可差 30%；上表同一行的前后数字都是同一时段测得的。

# 第二轮：控制中心入场、任务栏按钮与设置窗口合成（2026-11-14）

## 改了什么
- **控制中心入场/出场：** 面板从任务栏那一侧出来（任务栏在底部就从下往上），带一点缩放（入场 0.94→1，出场到 0.965），各排卡片依次浮现。打开和关闭都用 `ControlMotion` 弹簧，可随时中断反向。
- **打开延迟：** 新开的采集服务第一次 `ReadPixels` 要 150–200 ms。现在先用 `GlassBackdropService.ReadScreen`（一次屏幕拷贝约 20 ms）出第一帧，窗口采集预热好之后再接上实时合成。
- **开场跳变：** 亮度、音量、深浅模式、省电模式改在构造时就开始后台读取，并沿用进程内上一次读到的值。动画第一帧就是正确数值，不再从默认值跳过去。程序启动后第一次打开时还没有记住的值，亮度仍可能晚一点到。
- **任务栏按钮：** 任务栏也是置顶窗口，点击后会盖住快速设置旁的小按钮。现在每次扫描和点击任务栏后把按钮重新置顶。按下改由鼠标钩子直接响应。偶尔一次扫描没找到网络按钮时不再立刻隐藏，连续两次没找到才隐藏。
- **设置窗口：** 不再用分层窗口（`AllowsTransparency` 每帧要把整窗读回 CPU）。改成 WS_POPUP 窗口，透明由 DWM 合成；标题栏拖动、边缘和四角缩放、最大化到工作区，都由 `SettingsShellWindow.Composition.cs` 自己处理。同一页面滚动约 34–44 → 69–75 次更新/秒。没有了系统边框，拖到屏幕边缘贴靠和 Win+方向键不再可用。软件渲染时仍用分层窗口。

## 试过又撤掉的
- **入场时冻结玻璃：** 帧率能到 69–77 fps，但运动中玻璃显示的是最终位置下面的内容，看起来像贴图。用户否决，已撤掉，现在动画全程实时折射。
- **10 块玻璃合成一个着色器、一次绘制：** 截图确认画面正确，帧率和逐块绘制一样（约 52–55 fps），撤掉。

## 入场帧率瓶颈（测量框架，背景页面在动，只适合同一时段 A/B 比较）
| 去掉的东西 | 入场 fps |
|---|---|
| 不去掉 | 43–55 |
| 卡片内容、按钮高光、缩放、淡入、逐排浮现、每帧重映射 | 无明显变化 |
| 磨砂循环（每像素 75 次采样 → 3 次） | 无明显变化 |
| 卡片玻璃效果这一层 | 91–112 |

屏幕由 Intel 核显驱动。着色器计算量和绘制次数都不影响帧率，瓶颈在 WPF 给每块玻璃套效果的这一步，换着色器算法解决不了。出场约 90 fps。

## 验证
- 默认测试 73/73；entrance-motion、glass-alignment（24）、card-frost（15）、frame-ownership、capture-stamp、scaled-backdrop 通过；settings-polish 新增的无边框窗口检查通过。
- 已更新本机正在用的安装版（正常 `--shutdown` 后替换并启动）。

- 进一步提速只剩两条，都要用户决定：动画期间临时降低玻璃分辨率（碰到"不明显降低玻璃质量"的边界），或在 Windows 图形设置里让程序用独显（屏幕接在核显上，效果不确定）。
