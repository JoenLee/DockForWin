# WPF 动画性能与安全清理：2026-11-09

## 本轮结果

已合入一项经过对照的采样优化：只对同一 WGC 时间戳、同一源窗口位置/尺寸和同一采样区域，省去重复 GPU Copy/Map 与保存位图替换。新 WGC 帧、窗口移动、ROI 变化仍立即读回；无有效时间戳则走原读取。它减少后台 CPU/GPU 往返，没有降低背景检查频率，也没有用基于时间的旧帧代替新帧。保留上一轮 UI continuation 立即上传修复、所有 Shader/玻璃质量、动画曲线、布局、图标和交互。

未达到接近 180Hz 的验收，实际呈现 FPS 未可靠测得。动画 P99 波动仍明显；700MB 软目标未达到，未设置内存硬限或执行强制 GC/工作集修剪。

## 源码与瓶颈检查

- Rendering 注册仅出现在 Loaded，Closed 解除；当前工程每次唤出创建窗口，未发现重复注册路径。
- ControlMotion.Step 使用解析弹簧与真实 dt，不使用不稳定的逐帧 Euler 积分。本轮不改弹簧参数与时长。
- 展开共享内容原先已用固定宿主与 RenderTransform；玻璃外轮廓形变需要真实尺寸，未盲目替换 Width/Height。
- 基线 Rendering 业务计算约 0.26ms，ConfigureBackdrop 约 0.03ms/次。WPF 局部 Arrange 代码累计约 131.25ms/整轮；这些自计时不含整个 WPF 布局引擎、原生渲染线程和 GPU 等待，不能称其为完整 UI 帧耗时。
- 轮廓重建有重复分配，但分项成本不足以解释长尾。试验共享路径减少分配却没有改善长尾，未合入。
- 原 Shader 反汇编 247 指令槽、3 次纹理读取，高光条件判断前仍有纹理读取。固定通道试验为折射167槽/3纹理、高光171槽/0纹理；24组真实屏幕对照最大差1/255，最差平均0.000002/255。但该试验未改善帧时间，未合入；实际 HLSL/.ps 均保留原版。
- 可以确认的冗余：WindowFrameCapture.Read 对未变化的 Latest 仍 CopySubresourceRegion + 同步 Map。静态背景每组原有 3550 / 3565 次 GPU 复制，优化后 40 / 40 次；这是只在源确实不变时消除重复工作，不代表动态背景也会下降相同比例。

## 玻璃实时性与滑块

- 正确原版 Shader 构建中，最高画质静止背景、展开返回、窗口移动共12次变色均成功；实际工程重新构建后12次也成功，逐次日志 animation-lab/response-source.log。测试从背景属性变更计时，包含背景自己的WPF渲染、WGC采集和屏幕读取，不能等同输入到光子。高负载首例仍可达388ms，不能宣称全面消除玻璃延迟。
- 新帧/ROI/移动的 WGC 定向检查通过，实际工程新红色源帧观察到更新约15.23ms；这个小型检查不代表整控制中心端到端时延。
- 同条件真实鼠标滑块拖动：回调均值 16.20→15.22ms，P95 21.88→22.76ms，P99 93.46→91.08ms。注入输入至回调均值 4.65→4.94ms，差异小，不能宣称响应明显改善。该测试执行真实WPF拖动但屏蔽硬件音量写入，未验证音量设备COM路径或亮度硬件拖动。
